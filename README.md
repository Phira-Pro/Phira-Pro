# Phira Pro

Phira Pro 是基于 [Phira](https://github.com/TeamFlos/phira) v0.8.2 的**非官方改版**。

它在尽量不改变原有玩法与手感的前提下，补充了大量**练习、调试、外观自定义与本地成绩管理**相关的功能，适合练习高难谱面、研究判定手感或自建外观。

> **本项目为非官方改版，与 TeamFlos / Phira 官方没有任何关系。**
> 使用本改版产生的一切后果由使用者自行承担，请勿将本改版的问题反馈给官方。

## 下载

在 [Releases](https://github.com/Phira-Pro/Phira-Pro/releases) 页面下载 Windows、macOS、Linux 压缩包、Android arm64 APK 或 iOS 未签名 IPA。Windows 解压后运行 `phira-main.exe`，macOS / Linux 运行 `phira-main`；Android 更新时保留应用数据，iOS IPA 需自行签名安装。

当前源码版本为 **pro.17**（应用内 `0.8.2-pro.17`，build 92），包含谱面视频导出、Plugin API v3 和 PRCA 回放分析。本轮补齐 RPEN 0.13.1 的播放兼容和 Bezier 边界求值，修复练习模式调整结束位置时光标跳回开头的问题，并移除内置多人房间及实时观战功能。源码版本与已发布附件分别维护，实际可下载版本以 Releases 页面为准。

插件接口见 [开发说明](docs/plugins/README.md)，模块职责与审查方法见 [代码审查指南](docs/development/code-review-guide.md)。本版继续包含 [rpe-next 噪域兼容](docs/development/rpe-next-noise.md)、[回放录制与播放](docs/development/replays.md)及各平台帧率设置。历史更新见 [pro.16](docs/development/pro-16.md)、[pro.14-fix1](docs/development/pro-14-fix1.md)、[pro.14](docs/development/pro-14.md)、[pro.13](docs/development/pro-13.md)和 [pro.12](docs/development/pro-12.md)。版本维护、五个平台构建与 Actions 使用方法见 [构建说明](docs/development/build.md)。

课题模式保留三首连续游玩、黑场过渡、Saira 字体结算和五种课题牌子；课题结算详情与难度等级适配手机、平板。相关功能见 [pro.15 更新说明](docs/development/pro-15.md)。

PPSR 分析浮窗使用当前曲绘的暗色半透明背景，以圆角数字框突出总难度，保留拖动、收起及十项细分难度。

RPE/RPEN 导入按 JSON 结构选择主谱，排除附加配置、噪域数据和其他 JSON，优先使用主谱而非自动保存副本；重复导入和携带 `info.yml` 的二次导出保持同一谱面选择。读取支持 UTF-8 BOM 与前导空白，PPSR 使用相同解析规则。空 `extra.json` 无需 BPM，含定时效果或视频但省略 BPM 时沿用主谱变速表；显式附加 BPM 仍优先使用，损坏配置继续报错。

RPEN 0.13.1 的兼容范围与验证入口见 [适配说明](docs/development/rpen-0131-compatibility.md)。

## 相对官方版新增的功能

### 判定与手感

- **判定设置与预设**：从「设置 → 谱面 → 判定设置」进入独立页面，直接调整当前设置，也可添加、命名和保存预设。「复制为新预设」「修改预设」「添加预设」分别提供独立操作，已保存的自定义预设可再次修改；内置「Phigros本家判定」「Phira Pro判定」「细致判定」不可覆盖修改。
- **提前／延后独立区间**：各档分别设置两侧阈值，例如 Perfect+ −16ms / +20ms；同时提供匹配、保护、Hold 和严判选项。
- **判定颜色**：各档独立设置 RGB 颜色，随预设保存，应用于打击粒子、偏移条和结算名称；留空恢复资源包颜色。
- **Perfect+ 开关**：关闭时合并到 PERFECT，同时禁用理论值分数。
- **细致判定**：PERFECT+ → PERFECT → GREAT → GOOD → OK → MEH → BAD → MISS；两列结算及历史详情保留各档计数。
- **osu!mania ScoreV2 OD 快捷区间**：选择整数 OD −15～15 自动关闭 Perfect+ 并应用随 OD 变化的 PERFECT 等判定区间，随后可继续手动调整。实际半毫秒边界和所选 ACC 权重见 [build 56 说明](docs/development/pro-14-build-56.md)；计分与 Hold 规则仍按当前玩法处理。
- **晚按补偿**：把「按晚了」的误差整体减掉若干毫秒；设为 0 时不附加晚按补偿；提前和延后窗口仍可独立设置。
- **黄键／红键保护**：Phira Pro 内置预设默认开启，两项保护本身不影响成绩上传资格。可配置邻近 Drag / Flick 与 Tap 的点击匹配规则；本家流程包含提前侧的时间差比较、黄键单次保护和红键可重复保护。
- **连击文字**：自定义连击数下方那行文字（最长 16 个字符）。

### 练习与失败处理

- **自动重试**：失败后自动重开本局，可设置次数（0 为关闭）。
- **续练提前量**：重开时从失败前若干秒处开始，而不是从头开始。
- **变速练习**：练习时每完成一圈自动提速，可设置起始速度与每圈增幅；倍速、流速和提速步长精细到 0.01x。
- **分段练习**：保留原版速度滑条、区间时间轴与白底时间输入框；按时间或起止 Combo 指定区间，保留同刻音符与 Hold 尾部，支持自动循环。新增配置从左侧圆角菜单展开，Combo、自动循环、起始速度、每轮增速、失败重试次数、回退时长及多轮统计均收进菜单。
- **音频辅助与练习判定**：变速不变调、按音频时钟播放正解音、临时判定区间倍率及速度反向联动；不修改保存的判定预设。
- **谱面揭秘与音符行为**：缩放／平移谱面视角并同步触点坐标，缩小时高亮标出原始可见范围；临时转换为 Tap、Drag 或 Flick，随时恢复原谱。判定范围采用 Phira ad 的独立透明色带和描边，可显示在判定线／音符／两处，支持按音符类型、Tap／Hold 判定档位、Hold 尾部及透明度调整。
- **片段书签与多轮统计**：按谱面保存命名片段及练习参数；记录每轮速度、准度、判定数和最佳准度。详见 [练习功能说明](docs/development/pro-14-build-59.md)、[build 60 界面调整](docs/development/pro-14-build-60.md)及 [build 61 侧栏调整](docs/development/pro-14-build-61.md)。

### 血条

- 血条模式（扣到 0 本局失败）、扣血倍率、血条长度、厚度、整体倍率、颜色。

### 外观与界面

- **自定义外观**：图标、背景、立绘可自行导入替换。
- **主页音乐面板**：左下角水平面板提供进度、随机切歌、播放／暂停和歌曲信息弹窗；无自定义音乐时随机播放本地谱面音乐，从预览时间起播，有自定义音乐时循环播放。
- **自定义背景音乐**：导入 mp3 / ogg / wav / flac / m4a / aac 作为主界面背景音乐，可一键恢复默认。
- **界面主题**：自定义软件界面的强调色与表面色。
- **自定义字体**：导入 ttf/otf 作为界面字体，可一键恢复默认（重启后生效）。
- **显示帧率**：默认居中顶部，带背景衬底，可选择顶部／底部居中及四角；iOS 避让安全区域。
- **Windows 帧率上限**：在「设置 → 调试」选择跟随屏幕、60～480 FPS 的固定档位或「无上限」，立即生效并保存。「无上限」取消软件限帧等待，实际帧率受设备性能与驱动影响。

### 谱面协议与调试

- **rpe-next 噪域**：读取 Next 模式导出的 JSON/PEZ，支持全谱拍数、多段激活、独立动画轨道、锚点与反转选项，使用官方贴图、折射与辉光材质，并接入游玩触点拦截。显示适配与验证范围见 [兼容说明](docs/development/rpe-next-noise.md)。
- **彩色噪域**：支持 Line2Area / BlockAreaList 的噪域读取与颜色显示；Line2Area 在编谱画布内先旋转，再映射到谱面视口，保持相邻噪域的拼接与间距，并修正出现、预警闪烁和失效阶段的显示。
- **噪域与游玩界面**：官谱 JSON、RPE 和 RPEN 的噪域合成包含进度条、暂停按钮、分数、准度、连击、曲名、难度、偏移指示器和判定详情；暂停菜单与练习工具面板在合成后绘制，保持可操作。

- **判定线调试**：在每条判定线旁显示编号 / 线高 / z-index，本该隐藏的线以淡影保留。
- **音符调试**：在音符旁显示线号 / 时间 / 高度 / 类型，并画出横向判定范围。

### 结算与偏移

- **结算判定分布图**：以 0ms 居中画一张判定时间分布图（早 ← → 晚），左蓝右橙。
- **结算状态条**：依次显示适用的 `UNRATED`、Mod、`STRICT MODE`、OD 和谱面倍速，文字之间只用空格连接，不标注判定预设名或 `[i]`。多个 Mod 使用图标；AP／FC 挑战共用突然死亡图标，严格模式固定放在所有其他 Mod 后。单个 Mod 保留名称，严格模式和全 Tap／Drag／Flick 保留文字。没有状态内容时整条隐藏，有内容时点击白色区域查看本局设置详情。
- **状态显示例外**：自动游玩显示 `AUTOPLAY`，可附加倍速；OD 显示数值，例如 `UNRATED OD -4`。严格模式在其他上传条件满足时按 `STRICT MODE 1.10x` 显示，但仍不能上传成绩。完整规则见 [结算状态条说明](docs/development/ending-status.md)。
- **一键应用推荐偏移**：分析本局判定后直接应用推荐的整体偏移。

### 本地成绩

- **成绩历史**：本机保存游玩记录，可查看列表、趋势、PB 对比、判定分布对比，并支持导入 / 导出。细致判定单独保留完整档位，不覆盖原计分体系的最佳成绩。
- **回放文件管理**：从「设置 → 谱面 → 回放文件管理」统一导入、导出、关联和删除回放，单谱本地记录与成绩详情保留入口。新文件使用 `.ppr`，继续读取 `.phirar` / `.phirarec`；回放与谱面、音乐分离，缺少谱面时提供关联或在线下载入口。
- **他人回放**：导入后显示在对应谱面的本地记录中，保留原玩家与来源标记，可按来源和录制规则筛选；不计入本人的 PB、RKS 或统计，也不上传。
- **回放播放器**：连续拖动时间轴、观看倍速、实际录制帧步进、A–B 循环、BAD／MISS 定位、触点编号与显示调节、判定范围和录制信息。新格式保存原判定配置及真实误差，兼容旧格式；旧回放缺失的信息明确标为未记录。
- **单局录制隔离**：回放在正常结束并保存本局记录时落盘；未结算退出会丢弃这次录制，重新开始会立即清空上一把并重新记录，结算页再次重试也使用独立记录。

### 插件

- **Phira Pro Plugin API v3**：从「设置 → 通用 → 插件管理」导入 `.zip` Rhai 脚本插件，继续兼容 v1／v2。支持谱面与结算回调、谱面选择分析、JSON 设置，以及用户主动选择回放后的只读分析和报告绘制。实际算法由插件作者实现。见 [接口开发说明与可运行示例](docs/plugins/README.md)。
- **PRCA 回放分析**：从回放管理的「PRCA」入口选择回放、启动或取消分析，查看并保存报告图片。PRCA 0.3 需要 build 91 及以上宿主和对应插件；它是实验性证据工具，不输出作弊概率或自动作弊定论。支持范围和限制见 [PRCA 说明](docs/plugins/prca.md)。

### 谱面渲染（视频导出）

- **把谱面渲染成视频**：从「设置 → 调试 → 谱面渲染」进入独立页面。点击谱面卡片中的「选择」会打开独立选谱界面，挑一首后回到页面点「开始渲染」即可导出 mp4，输出到 `data/render/`（可改目录）。
- **完整演出流程**：保留默认纯谱面导出，并提供「Phira 游玩界面」和「Phigros 完整演出」预设。开场加载、谱面自动播放、结算可分别开关，开场、游玩入场、退场和结算时长可独立设置。Phigros 风格加载与结算使用斜切曲绘、曲目信息、玩家资料、动态分数与判定统计；展示值不写入成绩记录。局内进度不受谱面偏移影响，完整播放的末帧填满进度条。
- **分类设置与完整清单**：按输出、演出流程、开场、结算和音频分类，另有「参数总览」集中列出全部 47 项当前值。宽窗口双列设置，窄窗口单列设置；字段标签、说明和控件统一对齐，长文案按高度换行，底部操作与进度固定。完整字段见 [设置项清单](docs/development/chart-video-settings.md)。
- **独立渲染设置**：支持 720p / 1080p / 1440p / 2160p、30 / 60 / 120 / 240 FPS，以及演出字体、展示元数据、头像、RKS、课题牌子和自定义结算统计。音乐、打击音、结算音乐独立调节音量，支持结算音乐延迟，统一按视频时钟合成。设置保存在 `data/render.yml`，不改动游玩偏好；导出时不播放声音，可中途取消。
- **演出排版与进度**：开场与结算采用宽度归一化坐标及画面比例补偿，长标题自动缩小字号。Loading 白块从左向右伸长后向右收拢；加载末尾采用 RPE Recorder 的 3 秒退场时序，由真实谱面判定线与局内 UI 连续入场，默认提示沿用游玩加载条目。空格参与字体回退，保持正常字间留白。结算昵称底板随文字宽度变化，课题牌子使用五色背景素材，保留独立 RKS 栏。设置页不显示画面预览，导出时保留阶段、帧数、进度与预计剩余时间。

- **按需安装 FFmpeg**：Windows 页面会检测可用的 H.264/AAC 编码器，未安装时提供「下载并安装 FFmpeg」按钮，从 [gyan.dev](https://www.gyan.dev/ffmpeg/builds/) 下载 essentials ZIP，显示下载进度并支持取消和失败重试。下载包通过完整性校验、解压与实际编码验证后，安装到 `data/tools/ffmpeg/` 并自动使用，不修改系统 PATH，不增大主程序包；已有系统 FFmpeg 时可直接使用。其他桌面端仍需自行安装带 libx264 与 AAC 的 `ffmpeg`；Android 包已内置静态 FFmpeg（见下文）。
- **渲染内核与扩展**：`prpr/src/chart_video/` 分离配置、时间轴、演出画面、音轨、编码器和会话。预留独立原生扩展实例、逐阶段回调、逐帧行为、分层绘制与音频处理接口，详见 [扩展约定](docs/development/chart-video-extensions.md)；脚本插件适配尚未接入。命令行示例 `prpr/examples/render_chart_video.rs` 支持 `FULL_PRESENTATION=1` 启用完整演出。实现及限制见 [谱面渲染](docs/development/pro-17-chart-video.md)。
- **Android 构建**：`scripts/build-android-ffmpeg.sh` 会在 Gradle 构建时（任务 `ffmpegNdkBuild`）自动下载 x264 与 ffmpeg 源码并交叉编译成 `libffmpeg.so` 一起打进 APK，产物首次约需十几分钟，源码与中间结果缓存在 `target/android-ffmpeg`。渲染器的版本名为 `0.8.2-pro.17-render`（`applicationId` 与上游一致，安装会覆盖同名的官方包）。为了能启动这个内置的 ffmpeg 子进程，渲染器包的 `targetSdk` 是 28（Android 10+ 对 `targetSdk >= 29` 的应用禁止执行数据目录里的文件）。手机上渲染完成后视频会通过 MediaStore 存入系统「下载/PhiraPro」，可以直接在文件管理器里找到。

### 其他

- iOS「设置 → 调试」提供 60／120 Hz 和「无上限」选项，并接入 ProMotion 刷新率申请；「无上限」申请设备支持的最高刷新率。
- Android「设置 → 调试」默认申请 120 Hz，可选择 60、120、144、165、185、200、240 Hz 或「无上限」，并显示系统报告的设备最高刷新率。「无上限」申请系统报告的最高刷新率，支持超过固定档位的设备。窗口恢复、原生渲染恢复、显示状态变化及 Surface 重建时会重新申请；旧系统优先选择同分辨率下满足目标的最低档位，避免 60/144 Hz 屏幕在请求 120 Hz 时误选 60 Hz。诊断区分请求提交、应用刷新率报告与显示模式报告，详见 [Android 刷新率机制与验证](docs/development/android-refresh-rate.md)。实际刷新率仍受设备支持、系统游戏策略、省电和温控影响。
- 修正 Android 多指按下、移动、抬起及取消的触摸转发；修正 Windows / Linux 构建问题；内置 HarmonyOS Sans 及补充字体，覆盖语言菜单中的韩语、泰语等字符。

## 成绩与隐私

- 符合登录、谱面及默认判定／玩法条件的对局上传到 **`api.phira.pro`**（Phira Pro 自建成绩服）；非计成绩对局保留本地记录。
- 只有**未改动判定 / 玩法**的对局才会上传（`is_official_play`）：自动游玩、全屏判定、严格判定、判定窗口调整、晚按补偿、Hold 尾判、降速、键盘模式、离线模式等任一偏离默认值都不会上传，仅存本机；本家算法、独立两侧窗口、细致判定同样属于非默认判定。红黄保护、血条参数、流速和判定颜色允许正常计成绩。
- 单谱排行榜分为 **Pro榜 / 混合榜 / 本地记录**。混合榜按当前指标为每位玩家保留较优成绩，标明官服或 Pro服来源，不显示混合名次；个人排名分别显示官服与 Pro服名次。准度仅按已返回成绩排序，不显示准度名次。

## 从源码构建

需要 Rust（版本锁定见 `rust-toolchain.toml`，nightly）和 Python 3.8+，以及对应平台的编译环境：

```bash
python scripts/version.py check
python scripts/build.py
```

Windows、Linux、macOS 在各自系统上使用 `python scripts/build.py --package` 构建 ZIP，版本和平台名称自动派生；包内包含程序、资源与许可证。更新日志保留在 `docs`。Android 使用 `python scripts/build.py --platform android`，iOS 在 macOS 上使用 `python scripts/build.py --platform ios`。GitHub Actions 提供手动运行的 Desktop Packages / Android APK / iOS IPA 工作流；发布与版本定义一致的 Release 后，Build Release Assets 自动构建并上传五个平台附件，上传时校验文件大小与 SHA-256。iOS 产物未签名，安装前需自行签名。发版步骤、环境与签名配置见 [构建说明](docs/development/build.md)。
