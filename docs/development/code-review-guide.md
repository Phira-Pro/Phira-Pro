# 模块职责与新手代码审查指南

## 目前的实际情况

项目有模块划分，但还不能称为充分解耦。`prpr/src/scene/game.rs` 仍是较大的游玩协调器，共享 `Config`、资源状态与时钟；把代码移进不同文件也不等于消除了耦合。应逐步收紧接口，并在每次拆分时验证行为，而非一次重写整个游玩系统。

本轮将应用生命周期放入 `game/lifecycle.rs`，将 HUD 和操作控件的绘制入口放入 `game/render_layers.rs`。它们仍通过 `GameScene` 访问状态，这是职责拆分，不是已经实现了独立子系统。

## 哪个模块负责什么

| 目录／文件 | 主要职责 | 不应该承担的工作 |
| --- | --- | --- |
| `phira/src/page/`、`phira/src/scene/` | 客户端页面、谱面选择、设置和回放播放器 | 在页面内复制谱面解析或判定算法 |
| `prpr/src/parse/` | 将谱面格式转换为引擎数据 | 直接处理菜单或手机前后台事件 |
| `prpr/src/judge.rs`、`prpr/src/judge/` | 输入匹配、判定与判定结果 | 绘制练习菜单、写账户配置 |
| `prpr/src/core/` | 谱面对象、噪域采样与合成、资源和帧缓冲 | 决定暂停按钮或侧栏的布局 |
| `prpr/src/scene/game.rs` | 编排一帧的游玩流程和场景状态 | 继续堆入每个功能的完整实现 |
| `prpr/src/scene/game/render_layers.rs` | 区分游戏 HUD 与应用操作控件的绘制入口 | 改动噪域协议解析或音符判定 |
| `prpr/src/scene/game/lifecycle.rs` | 后台暂停、前台恢复、恢复前暂停状态和渲染缓存失效 | 重置练习段落、书签、成绩或用户倍速 |
| `prpr/src/practice/` | 练习控件、选项和练习音频流 | 改写局外全局倍速或读取账户信息 |
| `prpr/src/scene/game/practice.rs` | 将练习操作应用到游戏状态 | 单独实现另一套触点坐标或噪域绘制 |
| `prpr/src/viewport.rs` | 比例适配和视口坐标换算 | 读取谱面文件或修改 UI 设置 |
| `prpr/src/time.rs` | 时钟、暂停和显式跳转 | 通过恢复旧时间撤销用户的拖动操作 |
| `phira/src/replay.rs`、`phira/src/replay/` | 回放记录、格式、文件管理及播放定位 | 静默覆盖观看者的资源包选择 |
| `phira/src/plugins/` | 插件加载及插件接口 | 绕过正常数据和资源管理入口 |
| `phira-android/`、`xcode/` | 平台生命周期、系统能力和打包 | 另写一套与引擎不一致的判定逻辑 |

渲染顺序由游玩协调器决定。本轮明确为：

```text
背景、谱面与音符 → 噪域合成 → 游戏 HUD → 剩余全局效果与最终画面合成
                                                     ↓
                                    暂停／练习操作控件 → 外层界面
```

噪域算法本身仍负责谱面效果；操作控件不进入噪域的截图或后处理纹理。前后台恢复只使渲染缓存失效，下一次有效绘制时由资源模块重建，避免在 Android 生命周期回调中直接分配 GPU 对象。

## 不会写代码也能先检查这五件事

1. **是否对应你的问题。** 要求给出「什么操作会出错 → 改动点 → 修复后应怎样」。不要只接受“优化了”“重构了”。
2. **修改范围是否合理。** 修复练习后台恢复，涉及练习音频、生命周期和渲染缓存有理由；如果同时改动登录、服务器或计分，需要解释。
3. **原有数据是否保留。** 倍速、练习区间、书签、回放和本地成绩是否被重置？覆盖安装是否需要卸载？未经要求不能删除这些数据。
4. **测试是否真的触发问题。** 绿色标记应经过触摸分发、更新、渲染，不能只直接调用跳转函数；后台问题应模拟音频回调停顿和连续恢复；遮挡问题应真正渲染活动噪域并检查控件像素。
5. **产物是否来自这次代码。** 对照构建号、源码标识、打包日志与包校验值。测试通过不等于代码没有缺陷，但能明确已经检查了什么。

## 看改动，而不是从头看整个仓库

在仓库目录运行下面的只读命令。红色通常表示删除，绿色表示新增；先看文件列表，再看具体差异。

```powershell
# 本地尚未提交的改动：先看范围，再看内容
git diff --stat
git diff

# 已提交的某一轮改动
git show --stat <提交号>
git show <提交号>

# 比较你已验收的版本和待审版本
git diff --stat <已验收提交号> <待审提交号>
git diff <已验收提交号> <待审提交号>
```

新文件尚未加入 Git 时不会出现在普通 `git diff` 中，要一起查看 `git status --short` 列出的 `??` 文件。不要把用户截图、游戏数据或签名文件当作代码随意提交。

## 可以直接使用的审查要求

> 请只审查，不修改代码、不提交、不发布。审查范围是【起始提交】到【结束提交／当前本地改动】。重点检查：噪域是否覆盖操作 UI；练习前后台恢复是否死锁、黑屏或丢失区间；倍速与音频／时钟是否一致；本地数据是否受影响；模块是否越权或复制逻辑。每个确定的问题给出文件和行号、触发条件、实际后果及修复建议。没有证据的怀疑单独列出，不要当成已经确认的 bug。说明已有测试的覆盖范围与缺口。

先做一轮“只审查”，拿到问题清单后再决定哪些要修改，会比边审边改更容易核对。对渲染、Android 生命周期和音频线程，还应请有对应经验的人复核；代码审查与设备复测互相补充。

## 本轮可复验的检查

- 无音频回调消费时连续发送超过原队列容量的控制命令，界面线程能够返回；恢复音频消费后，暂停与跳转位置仍正确。
- 练习初始暂停状态连续切后台／回前台，时钟不自动前进，视口尺寸不变也会重建帧缓冲。
- 直接绘制、FXAA、MSAA 三种路径下，全屏活动噪域确实改变谱面像素，同时不破坏操作控件的白色像素。
- 继续运行已有的倍速、三色标记、比例、回放和资源包回归。

图形回归入口为 `phira/src/scene/replay/tests.rs` 的 `production_replay_transport_import_and_aspects`，音频队列测试在 `prpr/src/practice/audio.rs`。这些是桌面 OpenGL 和模块测试，不应写成“所有 Android 设备都已通过”。
