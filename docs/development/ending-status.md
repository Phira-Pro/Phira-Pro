# 结算状态条

状态条按顺序展示不能上传成绩标记、Mod、严格模式、OD 和谱面倍速。各文字元素只用一个半角空格连接，不显示判定预设名称或 `[i]`。原速不显示倍速，其他倍速保留两位小数和小写 `x`。状态内容为空时连同白底和点击区域一并隐藏；有内容时点击白色区域打开本局设置快照。

2026-10-27 的用户审核表保留在 `reviews/结算状态条文案审核-20261027.xlsx`。本次确认的例外如下：

- 自动游玩不显示 `UNRATED`，例如 `AUTOPLAY 0.90x`。这不改变自动游玩不能上传的规则。
- OD 显示明确数值，例如 `UNRATED OD -4`。审核表中个别条目的首尾空格不带入界面。
- 严格模式其他上传条件均满足时，按示例显示 `STRICT MODE 1.10x`。这是用户确认的显示例外，严格模式仍不能上传；离线、未登录、降速或其他不合资格条件仍显示 `UNRATED`。详情继续记录实际上传资格。
- 临时网络或服务器错误不改变这条状态文字，上传错误仍由原有提示处理。

单个 Mod 使用审核表中的名称。启用多个 Mod 时，有图标的项目改用图标，不再重复名称。AP 与 FC 挑战共用突然死亡图标，其具体模式仍列在详情。按用户本轮确认，严格模式和全 Tap、全 Drag、全 Flick 保留文字；严格模式文字固定放在所有其他 Mod 图标和名称之后。本轮补齐无失败和去连击分图标。过长的状态条自动换行，所有图标保留。本段空状态和严格模式位置约定包含用户看过实际截图后的进一步修正，优先于原审核表。

Mod PNG 统一放在 `assets/mod/`，新增图标的 SVG 源稿放在 `assets/mod/source/`。`core::ModIcon` 定义纹理槽位与资源路径，结算模块的 `mod_badges` 定义名称和显示顺序，`status` 生成不可变的本局状态，`status_badge` 只负责布局和绘制。上传规则仍由 `Config` 和原有上传入口负责。

验证包含状态文案、31 档 OD、严格模式显示与上传资格分离、多 Mod 图标顺序和长条换行。Windows 图形回归使用真实 PNG，在三种屏幕比例、三档字体大小下检查实际结算页和详情入口。
