# Linux 性能优化

## 帧率与音频

在「设置 → 性能 → 帧率设置」选择帧率上限。默认跟随屏幕，帧节奏由垂直同步决定。固定档位在更新和绘制前等待目标时间，仍受屏幕刷新率约束。选择「无上限」后，软件不再等待，并尝试关闭垂直同步。

应用默认使用 X11/GLX，在 Wayland 会话中可通过 XWayland 运行。运行时根据当前 GLX 屏幕公布的扩展依次尝试 EXT 和 MESA。SGI 只能用于恢复垂直同步；如果图形后端或驱动不支持关闭垂直同步，「无上限」仍可能受刷新率限制。重启时窗口会使用已保存的交换间隔请求。

「设置 → 音频」可切换设备默认缓冲和 128、256、512、1024 帧。遇到音频断续时可以试用更大的缓冲，代价是增加延迟。设置在创建新的音频设备时生效。

## 调度和内存

- Linux 渲染线程缩短计时器松弛时间，并在现有系统权限允许时请求调度优先级。i915 图形上下文的优先级也按驱动能力和权限尝试申请，可用 `PHIRA_DRM_PRIORITY=0` 关闭该请求。
- 后台每两秒采样进程的 DRM 内存统计及系统内存。对同一渲染节点上的 DRM 客户端去重；这里的计数可能包含系统内存分配，不等于独占显存。
- 字体图集从至多 1024 × 1024 开始，按需增长到 2048 × 2048 或设备上限。进入严重内存压力时，已扩大的图集会在下次绘制时缩回初始尺寸；回收请求至少间隔 30 秒。应用不修改系统的 TTM 参数。
- 游玩和练习所需的谱面内容完成解析及练习标识计算后，释放原始谱面文件的字节副本。该行为适用于所有平台。

## 验证入口

在 Linux 桌面运行以下命令，并在游戏中切换三个帧率模式。可在原生 Wayland 下用探针做对照，游戏仍默认使用 X11/GLX。

```bash
cargo test --locked -p prpr --lib desktop_
cargo build --locked --release -p phira-main
FRAME_PROBE_PACER=1 FRAME_PROBE_LIMIT=30 cargo run --locked --release -p prpr --example frame_pacing_probe
```

将探针的 `FRAME_PROBE_LIMIT` 改为 0 或 65535 分别验证跟随屏幕和无上限。用 `FRAME_PROBE_WAYLAND=1` 启用探针的原生 Wayland 模式。
