# pro.12

源码版本 `0.8.2-pro.12`，Android versionCode / iOS CFBundleVersion 为 `48`，统一维护在根目录 `version.json`。本文件说明当前源码的功能；已经发布的下载文件以 Releases 页面为准。

## 判定设置

入口为 **设置 → 谱面 → 判定设置**，不新增独立设置侧栏。当前设置可直接修改并自动保存；添加预设用于保存、命名和复用组合，支持取消草稿、编辑、重命名及删除。内置 Phigros本家判定、Phira Pro判定、细致判定。

每档可分别设置提前／延后阈值，例如 Perfect+ −16ms / +20ms。本家流程的严判基础区间、Drag 区间和 Flick 倍率也支持分侧配置；非法数值拒绝写入，阈值按等级顺序归一化。旧配置继续使用原有对称区间。

Perfect+ 可关闭：普通模式只剩 PERFECT / GOOD / BAD / MISS，原 Perfect+ 计入 PERFECT，理论值分数随之禁用。细致判定提供 PERFECT+ / PERFECT / GREAT / GOOD / OK / MEH / BAD / MISS，关闭 Perfect+ 时保留七档。结算和历史详情保留原来的粗体、灰白文字及提前蓝色／延后橙色，两列各最多四项，按实际字宽收紧两列并约束在右侧面板的倾斜边界内，位于 RETRY 左侧；连击栏保留原位置。推荐偏移按钮在平板和常规横屏中恢复到 RETRY 左侧，仅在极宽屏与详情重叠时移到上方。提前／延后数值与判定名称采用同一字号、垂直居中对齐；长数字按实际宽度整体缩放。

## osu!mania ScoreV2 OD 快捷设置

下拉选择整数 OD −15～15 后，自动开启扩展档位、关闭 Perfect+ 并应用以下对称宽判阈值；不覆盖已保存的命名预设。手动改为不对应任何 OD 的区间时显示自定义。

| 档位 | 半窗口（ms） |
| --- | --- |
| PERFECT+ | 关闭（保留的编辑值不参与分档） |
| PERFECT | OD ≤ 5：22.4 − 0.6 × OD；OD > 5：24.9 − 1.1 × OD |
| GREAT | 64 − 3 × OD |
| GOOD | 97 − 3 × OD |
| OK | 127 − 3 × OD |
| MEH | 151 − 3 × OD |
| BAD | 188 − 3 × OD（使用 mania MISS 点击窗口外边界） |
| MISS | 沿当前算法的未命中／过期规则 |

依据 [osu!mania 官方判定说明](https://osu.ppy.sh/wiki/en/Gameplay/Judgement/osu%21mania) 的普通原生谱面、ScoreV2 名义半窗口；普通非 ScoreV2 的 PERFECT 固定为 ±16ms，本快捷项按用户选择采用随 OD 变化的 ScoreV2 公式；[官方通常的 OD 范围为 0～10](https://osu.ppy.sh/wiki/en/Beatmap/Overall_difficulty)，−15～15 是按用户要求外推的范围。

此项只设置区间，不移植 mania 的计分、整数误差舍入、自动 Miss、不可 late MEH、Hold 释放或转谱规则。Perfect+ 自动关闭；算法、严判和保护等其他选择保持原值：Pro 严判仍将宽判减半，本家流程仍使用其独立严判参数。

## 细致判定与兼容

默认半窗口为 16 / 40 / 70 / 100 / 130 / 160 / 220ms；对应准确率权重为 1 / 1 / 0.85 / 0.65 / 0.50 / 0.25 / 0。窗口和权重是项目选择，不宣称使用 osu! 的计分规则。每侧阈值可编辑，未提供权重／颜色编辑器。

PERFECT+ 至 MEH 保持连击，BAD / MISS 断连；GREAT / GOOD / OK / MEH 会失去 AP。细致判定仅保存本地历史，不上传为原计分成绩，不覆盖既有本地最佳。历史新增可选完整等级计数，旧记录兼容。

本地回放 v4 保存判定档位开关和新增等级，兼容旧版本及 JPhiraRec v0/v1；旧事件码含义保持不变。

## 主界面音乐面板

左下角提供与游玩按钮同宽的扁平水平音乐面板，默认左边界与左上角 PHIRA PRO 标题对齐，不参与右侧按钮的倾斜变换。在 HUD 自定义的主菜单中可拖动 `music` 面板并保存位置。进度条使用深灰色圆端轨道和白色已播放部分；右侧依次提供等宽的随机切歌、播放／暂停图标按钮，随面板降低高度一起缩小。复用现有重试、恢复及游戏暂停图标；保持素材比例，排除透明留白的影响，统一可见图形高度，不显示按钮文字。歌曲信息框使用透明度更高的背景。

有自定义背景音乐时，循环播放该音频、禁用随机切歌。没有自定义音乐时，从本地谱面库随机挑选可读取的音乐，从 `previewStart` 开始播放到歌曲结束，再随机换曲；预览起点无效时从零开始。多个谱面可用时优先避开刚播放的谱面；缺失／损坏的音乐会跳过，无可用音乐则保持空闲。点击进度条打开半透明歌曲信息框，显示名称和当前时间／总时长；屏幕底部空间不足时向上展开。

读取、解码和响度计算使用后台任务，复用 UI 音频管理器。手动暂停状态保留到切换页面和应用恢复后；退出菜单进入游玩时停止菜单音乐。自定义音频导入会保存原文件名供信息框使用，已有导入缺少名称时显示保存文件名。

## 安卓输入与彩色噪域

多指触摸转发按 Android pointer ID 保留每根手指，分别处理按下、移动、抬起、历史采样及取消。Java 回归覆盖 3～10 指序列；系统三指手势拦截和具体设备硬件仍需实机确认。

保留此前的彩色噪域读取，补充视口、遮罩及边缘色的修正，相关回归脚本为 `scripts/verify_block_viewports.py`。隐藏桌面 GPU 结果不能替代 iPad / iOS 或安卓实体设备的验收。

## 验证与构建

核心 Rust 回归 145 项、应用回归 26 项、独立隐藏 OpenGL 面板及结算回归 1 项，共 172 项通过；图形回归覆盖 4:3 / 16:9 / 21:9、真实下拉选择、全部 31 个 OD 值、普通计数／早晚详情、偏移按钮和六位计数，并检查标签实际边界、数字完整宽度及紧凑列间距。新增音乐回归覆盖生产面板在三种比例下的显示、进度条信息弹窗及播放按钮点击，并通过实际 WAV 解码／音频流验证预览起播、随机切歌、暂停恢复、结束换曲、自定义循环和恢复默认。此前版本和打包工具回归 17 项、安卓 Java 路由回归通过，本轮未修改这些工具。

音乐面板后续调整复测了布局单元测试和完整 GPU 回归：在三种比例下测量随机、播放、暂停图标的实际像素边界，检查可见高度和素材比例；通过真实 HUD 编辑器拖动，保存后重新读取布局，并点击移动后的播放按钮。HUD 保存回归使用独立临时数据目录，退出时恢复原路径和布局，不写入用户配置。

Windows 与 Android arm64 release 已构建并校验签名、版本、包内程序及校验和。本轮没有完成 iOS IPA、Linux / macOS 构建或手机平板前台人工验收。构建与 Actions 使用方法见 [构建说明](build.md)。
