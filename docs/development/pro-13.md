# pro.13 更新与验证说明

源码版本：`0.8.2-pro.13`，内部构建号：`50`。

## 修复内容

- 回放文件管理页的「导入」「刷新」与最后一个筛选按钮右侧对齐；从设置页返回时，管理页内容参与原有页面淡出，避免按钮残留。
- 成绩/回放详情页底部按「返回 → 导入 / 管理回放 → 播放回放」排成同一横排。细致判定在宽屏手机上收紧按钮宽度并适配文字，避免上移或覆盖判定详情。
- Line2Area 的位置、尺寸、旋转及锚点统一先在 1350×900 编谱画布内计算，再映射到实际谱面视口。修复旋转后的连续噪域出现缝隙，以及跨屏幕比例时空隙变化的问题。父子线偏移使用同一变换顺序。
- Line2Area 出现时直接显示预览层；启用前最后 0.5 秒显示预警闪烁，启用时切换活动层，失效后回到预览层。生命周期继续读取 speed 协议，alpha 不决定生命周期。
- Line2Area 补齐 Recorder beta3 的独立 Ready 闪烁项，并用谱面时间推进效果；暂停、跳转及同一时刻重复渲染的相位保持一致。原生 BlockAreaList 保留原有材质路径。
- 保留全部语言选项，为所有界面文字画笔接入包内补充字体，解决韩语和泰语名称不显示的问题。
- Phira Pro 判定把黄键的「已参与点击匹配」与「已进入正常判定」分开保存；黄键只保护一次，红键在真正判定前仍可保护多次。多个相邻红黄键按谱面时间顺序处理，避免只选择绝对时间差最近的一键。

## 判定审查范围

分别检查 Phigros 引擎与 Phira Pro 引擎。Phigros 引擎已有独立点击标记和顺序匹配，本轮补充多保护键及同帧连续点击回归；Phira Pro 引擎修正上述状态混用与保护键选择问题，保留其原有空间匹配和可配置判定窗口。

保护条件按用户指定的[判定分析文章](https://www.bilibili.com/opus/1226031520301449218)核对，包括蓝键位于提前侧、至少 10ms 的时间差、黄键单次及红键重复保护。这是社区分析依据，不是官方公布的判定源码。代码和合成输入测试不能证明与本家所有设备上的手感一比一一致；该结论还需要本家与本应用的相同触摸轨迹对照。

## 可重复验证

两个脚本都只读取案例谱面，输出日志、截图和成功报告到 `target`。失败会停止流程，删除旧的成功报告；修改后重复执行同一命令即可复验。

```powershell
$env:RUSTFLAGS='--cfg record'
python scripts/verify_pro13_noise.py --brain '<ブレインロット谱面目录>' --milk '<MilK.pez>'
python scripts/verify_block_viewports.py --chart '<MilK.pez>' --output target/pro13-white-check
```

- 实际谱面回归：六种窗口尺寸，检查编谱像素坐标下的四个角点及同时间重复渲染的图像哈希。包含ブレインロット出现/启用阶段与 77 combo 波浪，以及 MilK 开头三色块间距。
- 白色边缘回归：六种窗口尺寸 × MSAA 1/2/4 × 两次重复，共 864 个 GPU 探针帧；另检查 MilK 102 combo 的 48 个实际游玩帧，覆盖普通与简化噪域显示。
- 原生材质回归：使用本地提取的原始片元着色器作独立参考；几何遮罩另与 GPU 栅格化参考比较。原始参考素材不随仓库分发。
- 回放页 GPU 回归：三种比例及设置页返回过渡，断言淡出结束后没有可见按钮；语言菜单逐字检查字形及轮廓；两套判定覆盖 10ms 边界、黄键单次、红键重复、多个保护键和连续点击。

噪域闪烁还使用本机 Recorder 3.2 beta3 的隔离副本做黑背景对照：出现后立即可见，启用前 0.5 秒闪烁；完整覆盖内部的闪烁增量拟合约为 `0.2393 × 255 × (1 + 0.5 sin(37.9t))`，与两个 `0.12` 项吻合。着色器文件中也分别存在 Ready 材质和 ActiveBlock 内的 Ready 项。该测量用于核实闪烁项，不代表两个程序的压缩视频逐像素一致。

上述 GPU 验证运行于 Windows OpenGL，模拟不同谱面视口；不等同于 Android 或 iPad/iOS 真机验收。宽屏窗口仍遵循用户设置的谱面比例与留边。
