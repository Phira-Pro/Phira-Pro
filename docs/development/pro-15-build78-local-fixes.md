## 布局与诊断

- 主菜单音乐面板的默认宽度固定为原始 0.83 UI 单位，继续使用独立的 `home/music` 槽位，不再读取用户调整后的 `home/play` 宽度。
- 谱面库课题入口使用独立 `library/course` 槽位，默认贴近页面底边，不再跟随用户调整后的列表底边。课题的开始按钮与计数跟随课题入口。
- 进入问题诊断不会自动开始采样。开始/停止保留记录；清空保留当前运行状态；跨页面开关仅控制退出页面后是否继续。未开启跨页面时离开会停止。
- 原始输入只存数值事件，不再对每次移动格式化字符串。预览每 200ms 取最近 240 个主循环间隔、12 条输入事件、120 个显示回调；统计排序在刷新预览时执行。触点位置每帧读取，避免预览频率限制触点移动。
- 导出时再获取完整有界记录：7200 个主循环间隔、20000 条输入事件、7200 个显示回调；JSON 包含导出时是否仍在采样。数据仅保留在本次运行内存。

## 刷新率

- Android 的失焦与失去 top-resumed 状态不再等同于后台。在 Activity 仍 resumed、窗口仍可能可见时补发 Surface 刷新率请求；恢复焦点再补发。仍只延后重试 300ms / 1000ms，真正暂停时取消。
- Android 浮窗遮挡期间只允许无缝切换，恢复自身焦点后才允许系统执行非无缝切换，避免浮窗开着时反复触发显示过渡。
- iOS 监听游戏窗口重新成为 key window，重新应用显示链接偏好并重置恢复预算。忽略其他窗口成为 key window。
- iOS 总回调耗时包含呈现等待，不能直接当成纯渲染负载。稳定低于目标 90% 时允许先探测一次；第二次重建仍要求有负载余量。每次激活/设置最多两次，低电量或严重温控下不重建。
- 这是对系统的刷新率请求与有界恢复；不宣称绕过系统或厂商的限帧。API 依据：[Android 多窗口](https://developer.android.com/develop/ui/views/layout/support-multi-window-mode)、[Surface 帧率](https://developer.android.com/media/optimize/performance/frame-rate)、[Apple 显示链接偏好](https://developer.apple.com/documentation/quartzcore/cadisplaylink/preferredframeraterange)。

## 严判作用域

判定设置保存在全局配置，本曲 Mod 保存在本曲配置。启动单曲时通过 `Config::chart_mods` 合并，两处的严格判定使用逻辑或；全局开、本曲关仍然严判，两处同时开只应用一次。不会回写另一处，也不会变为四分之一窗口。Perfect+ 保持用户配置值。

## 回放

- 录制触点驱动真实噪域覆盖检测、按压显示和原有音乐低通滤波，不依赖“显示触点”按钮。
- 跳转重建会按录制帧与输入事件的时间顺序恢复屏蔽状态，覆盖区域移动到静止手指下方的情况。缓存保存仍未松开的屏蔽手指，松手或 ID 复用后清除。
- 暂停与后台暂停滤波，继续播放恢复；普通时间轴拖动维持静默。
- 向前逐帧正常应用该帧判定并推进粒子；向后逐帧重建目标时刻的短暂特效，不重播历史打击音，不重复累计分数。暂停后粒子时间冻结。
