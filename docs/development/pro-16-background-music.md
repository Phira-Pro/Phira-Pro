# 背景音乐检查与修复

版本：pro.16，内部构建号 81。

## 已复现的问题

音量配置为 0 时，音乐时间和主页进度条仍正常推进，但音频流振幅为 0。旧面板显示暂停图标，点击只能在无声播放和暂停间切换。本机一套已有安装的背景音乐音量为 0；隔离测试目录也复现了这一表现。非零音量下，修复前程序能输出测试音，因此不把本次现象写成所有 Windows 音频后端均已失效。

## 修复范围

- 静音时显示播放图标，详情说明点击播放可恢复声音；启动和普通恢复仍尊重用户静音选择。
- 用户主动点击播放时，恢复当前实际生效的音量项：普通模式恢复背景音乐音量，统一音量模式恢复统一音量。保存失败则回滚配置。
- 每帧比较有效放大系数，仅在变化时同步到音频流。预设、配置恢复及场景返回不依赖某一个音量通知标记，也不重复塞满音频命令队列。
- 手动恢复播放使用淡入，取消可能残留的淡出状态。保留手动暂停和本地曲库预览、随机、历史逻辑。
- 自定义背景音乐继续通过音频后端的零交叠循环播放同一段 PCM；没有在每次循环时重新解码或改播本地谱面。

共享实现在 `phira/src/menu_music.rs`，不增加 Windows 专用播放分支。

## 验证

- `production_panel_save_cancel_reload_and_aspects` 通过。测试音频改用生成的非静音 440 Hz WAV，验证普通静音及统一音量静音恢复、保存、无通知标记的音量同步、手动暂停/场景恢复、本地曲结束换曲、自定义音频连续三次循环及恢复曲库。
- Windows 桌面使用隔离数据实际点击播放、暂停、恢复；输出设备回环测量只计算统计数值，不保存录音、不采集麦克风。静音/暂停 RMS 约 `0.000017`；恢复后主频为 `440 Hz`。
- 六秒自定义音乐连续采样 25 秒，跨过四次循环边界。每个 0.25 秒窗口 RMS 均不低于 `0.4472`，未出现停止输出；保存的背景音乐音量从 0 变为 1。
- Android `cargo check -p phira --lib --target aarch64-linux-android --no-default-features` 通过。iOS 应用库跨平台检查受 Windows 主机缺少 Xcode 的 `xcrun`/SDK 限制，未将其记录为通过。
- Windows 使用 `scripts/build.py --platform windows --package` 从本次源码构建。
