# PRCA 0.3：回放证据分析插件

PRCA（Phira Cheating Analysis）是可独立安装的 Plugin API v3 插件。0.3 需要 Build 91 及以上的宿主与本次插件同时更新。需要包含 API v3 和回放分析入口的宿主；不能在旧版宿主中只换 ZIP 使用。v1/v2 既有插件继续兼容。

## 安装与使用

1. 在「设置 → 通用 → 插件管理」导入 `Phira-Pro-PRCA-v0.3.0-experimental.zip`，手动启用。已安装旧版时先删除旧插件再导入；作者为 Kenari_15。
2. 打开「设置 → 谱面 → 回放管理」，左下角有独立「PRCA」按钮。管理列表再次点击已展开项可收起详情；右上角搜索框复用设置、谱面库的控件。
3. 进入 PRCA 后点击本地回放会高亮选择，再点击「开始分析」。导入单个文件后自动分析。顶栏使用返回箭头与 PRCA 标题；第二行依次为「本地回放」「导入回放」「开始分析」「查看结果」。分析时「开始分析」原位切换为「取消分析」。后台独立线程显示阶段与校验步骤；谱面解析使用可取消的轮询驱动，不依赖游戏加载界面的逐帧执行。异常和超时会返回明确错误。
4. 分析完成后自动弹出图片窗口。默认按窗口宽度显示报告顶部，支持拖动、双指或鼠标滚轮缩放，亦可使用放大、缩小、适应窗口按钮。底部「保存图片」在 Windows 写入系统图片目录下的 Phira Pro 文件夹，在 Android/iOS 通过原生相册接口保存。保存失败会提示，不覆盖既有照片。
5. 原始报告仍保存在用户数据目录 `replays/analysis/`，通过「查看结果」重新打开图片窗口，JSON 可直接从报告目录取得。普通回放导入和播放不触发 PRCA。

缺少谱面时仍生成基础图；需要完整计时分析时，先在回放管理关联录制版本再重新分析。谱面内容不匹配时不能使用同名谱面冒充。音乐匹配结果独立显示。

## 当前算法与结论

测量包括：完整接触时长、真实 Tap/Hold 头判误差、Hold 尾判统计、接触并发、连续接触速度、同帧原始触摸跨度、落点候选横向余量、误差分布、输入与谱面头部密度、误差序列周期，以及后端事件/输入订阅/录制消费之间的时间差。

Drag/Flick 的合成 0 和 Miss 占位值不计入真实计时统计。不跨接触计算“手指瞬移”，不把接触 ID 视为物理手指。轨迹图只连接同一接触的实测点。落点候选不是已证明的精确输入归属，不能代替完整输入重判。复杂噪域场景不执行简化落点核对。

插件独立定义规则及未校准的诊断画像：多个不重叠区间的误差集中、原始触摸按压时长重复，以及已校验谱面的判定引用/阶段一致性冲突。触摸细微计时集中检查要求后端时间与无已知丢样；键盘可用真实有符号误差完成基础检查，细微计时集中需其他证据支持。Phigros 帧判定与旧回放不执行子帧精度异常推断。不会把同一误差分布的多个统计量当作独立证据加分。

**当前版本是实验性证据工具，尚未完成人群校准，不输出作弊概率或自动作弊定论。** 报告采用 Plana 的浅色配色与圆角卡片，右上角绿底白字「正常」、黄底白字「存疑」、红底白字「存在作弊」。只有具体异常证据触发「存疑」。样本确实较少显示灰色「数据不足」，文件一致性问题显示灰色「数据异常」，两者不表示玩家作弊嫌疑。红色结论只接受经校准、有两个不同证据方向确认支持的结果，当前未校准画像不会自动升级到该结论。尚无真实数据支持任何误报率/检出率承诺。

频谱、轨迹、同步及落点目前提供观测图用于复核，不独立升级作弊结论。完整历史规则输入重判、跨回放模板库与可信设备认证不包含在 0.3 的结论覆盖中。缺少真人与受控异常语料时不应启用自动强异常认定。

## 0.3 的样本组织与判定覆盖

- 基础覆盖按项目分别判断。16 个有效计时组或 16 次完整按压可以完成对应基础观测，不再要求触摸后端时间才能显示正常。正常的含义是本次可用检查未发现需复核异常，不是已通过所有可能的检测。
- 每块固定 32 个有效操作，按操作数而非固定秒数划分。短谱、慢速稀疏段与密集长谱采用相同局部粒度；尾块不足 32 次仍保留统计，但不参与窄峰异常触发。计时检查要求至少 2 个不重叠块，键盘时长单独提示需要至少 3 块，或至少 2 块并有计时集中支持。
- 同一记录时刻的多个音符取误差中位数，仅计一个有效计时组。这里的“有效”是去除和弦重复计数，不能理解为统计学上完全独立；相邻操作仍可能相关。
- 键盘逐键配对 down/up，触摸按接触生命周期配对，但不把触点 ID 当作物理手指。暂停、取消、截尾、自动重复不算完整按压。键盘模式下辅助鼠标事件保留在原始回放，排除在主要按压统计之外。
- 时长候选要求同一通道的 1 ms 窄峰反复出现、按下间隔仍有变化，并排除明显帧周期量化。记录缺口、顺序修复、时钟不相容会停用受影响的精细检查。某个固定时长、低误差或高准度本身不直接定性。
- 输出峰占比与 Wilson 二项近似区间下界，帮助暴露小样本不确定性。下界既不是作弊概率，也不能消除序列相关、设备量化或选择偏差；画像阈值仍是未完成人群校准的诊断规则。
- 原生层保存全部固定块，插件通过 `replay_observations(kind,start,count)` 分页读取，每页最多 256 块。输入上下文只传块数和概览，不把整段原始数据搬入脚本；长谱不会通过放大样本块而稀释局部异常。
- 报告的“检查覆盖”逐项显示已检查、已观测、不适用、样本少、未启用。键盘不需要触点轨迹；不适用项目不会拖低总结果。

本次修复源于正常键盘回放已有 1804 条命中样本、1823 次完整按压，但旧版仍返回 limited：旧规则错误地把触摸专用精度要求作为全部正常判断前提，并将 limited 渲染成黄色存疑。0.3 不包含针对玩家或单份回放的白名单。

## 研究参考

- [Circleguard 帧间隔教程](https://github.com/circleguard/circleguard/wiki/Frametime-Tutorial)解释帧间隔误报与多峰分布。这里只参考检查采样机制、保留解释的做法；osu! 的 16.67 ms 等阈值不适用于 Phira 可变帧率，未移植。
- [minisbett/holdtimeanalyzer](https://github.com/minisbett/holdtimeanalyzer)提供按压时长观测图，作为按压配对与分布展示的参考。
- [source-dan/osu-replay-analysis](https://github.com/source-dan/osu-replay-analysis)展示从回放提取按键事件和时长的工具。PRCA 仍基于 Phira 判定、速度、触摸/键盘来源设计规则，没有复制这些项目代码，也没有把这些项目当作真人训练语料。

目前只有本地正常回放和受控合成异常用于回归，不足以估计实际误报率或检出率。外部项目的图形、阈值或名次不能替代经过标注的人群数据集。

## v6 录制与精度

新录制 v6 将原始输入流与旧播放兼容数据分开保存：后端触摸时间（存在时）、输入订阅时间、顺序、完整 ID、down/move/up/cancel、鼠标和键盘事件、每帧消费时钟/视口/速度/活动状态锚点。

新播放器根据这些事实派生触点时间与坐标，保留子帧操作先后。原始输入不排序改写；取消与松手仍分开保存在原始流。暂停接触在派生播放层关闭，不算生理松手。后台/暂停状态与事件时间基准不足时不进行高精度推断。

Windows 鼠标/键盘的现有后端接口未提供原始事件时间，因此记录输入订阅时刻，并明确标为非硬件时间。触摸是否有后端时间取决于平台。当前不宣称已经补齐 Android 批量历史移动样本或完成 Android/iOS 真机验证。未观察到的操作不能由插值补成证据。

原始输入上限为每帧 16,384 条、每局 200,000 条和 240,000 个锚点。超限记录缺口，报告降级；有已知缺口时播放回退到原有触点流。回放文件仍有 128 MiB 上限。v6 可读取旧格式，旧程序无法读取 v6；没有原始输入的旧回放继续导出 v5。

## 宿主与插件职责

宿主提供只读测量、分块读取、后台调度与受控绘图。PRCA 的画像、规则、证据选择及解释在 `examples/prca/main.rhai` 和 Manifest 中；宿主不按 PRCA ID 写死判定。

打包：`python scripts/package_prca.py`，默认输出到 `E:/Phira Pro/dist/plugins`；Windows 程序包仍放在 `dist/windows`。源码为 `docs/plugins/examples/prca/`。规则更新需按插件管理原有流程删除旧包后重新安装；生成报告保留。
