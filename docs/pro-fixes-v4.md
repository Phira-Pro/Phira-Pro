# Phira Pro 第四轮通用修复（2026-10-03）

应用显示版本仍为 0.8.2-pro.6；v4 指验证批次。

## 后续修改：移除序列码与解密码（尚未编译）

按用户最新要求，Windows、Android、iOS 和 Flash 共用的授权模块、启动验签、页面操作拦截、设置输入/确认/复制控件、数据迁移限制、配置字段以及 15 种语言的授权文案已删除。主工程与 iOS 源码副本均已同步删除；解密码生成工具和专用 Ed25519 依赖也已移除。

旧配置中的 `activationSerial`、`activationCode` 是未知字段，现有 Serde 配置继续忽略它们，下一次保存不会再写出；无需删除用户配置、谱面或历史记录。未新增授权开关或启动网络检查。

本次仅做静态验证：扫描 1042 个源码、资源与配置文件，授权功能引用为零；主工程和 iOS 的 Rust 文件通过语法解析，共享生产源码逐文件一致；Cargo/TOML、打包脚本 Python 语法和 iOS plist 解析通过，Git diff 空白检查通过。这些检查不替代编译和实机测试。

这一修改之后没有编译、运行 Cargo 检查/测试、签名或打包。下文构建和 66 项测试结果属于此前版本；目录中已经生成的 v4 ZIP、EXE、SO 和 APK 不包含此次移除，不能当作最新无授权版本发布。打包脚本会拒绝使用早于源码的 Windows/Android 二进制。

## 成绩目的地

此前游玩上传回调先调用官服 `/play/upload`，再额外上传 Pro。现在只有 Pro 上传；通用 POST 入口也将成绩请求强制转到配置的 Pro 地址。专用连接池禁止所有 HTTP 重定向，拒绝官服主域及子域作为目的地。Pro 地址为空、不可用、错误或返回重定向，都不会回退官服。登录、谱面和用户资料等原有只读官服功能继续使用原连接池。

上传取得的 record ID 属于 Pro。配置 Pro 的联机成绩校验也从 Pro `/record/{id}` 获取，失败不会拿同编号官服记录替代。联机服务器必须配置相同记录来源，见 `E:\Phira Pro\docs\phira-pro-api.md`。没有向外部服务器发送测试成绩；307 重定向回归只用两个 localhost listener。

## 结算误差

旧结算使用去掉平均偏移后的标准差，但上传 token 使用 RMS；每个 note 都晚 20ms 时，旧界面会显示 0ms。现在结算和编码共用同一函数：

`RMS = sqrt((sum(real_offset_seconds²) + miss_count × 0.25²) / total_note_count)`。

Miss 按既有协议计 250ms，自动判定的 note 在总数中计零误差。界面以毫秒显示到小数点后两位。推荐偏移仍使用真实命中偏移的均值，判定条标准差统计仍是原来定义；不混用 RMS。未改变 token 布局。旧历史记录没有原始逐 note 偏移，无法无损重算，保留原值；新的记录采用统一 RMS。

## 批量导入与迁移

导入时以真实临时目录解析、验证文件，修复验证尚不存在的逻辑下载路径导致的 os error 2。ZIP 根目录识别按路径 component 处理，支持 Windows、Unicode、隐式目录与扁平 ZIP；解压前验证全部 enclosed paths。

批量任务逐文件记录成功、跳过、失败，失败后继续导入其他文件，完成时排空进度 channel，保留并保存已经成功的条目。只有 metadata、chart、music、illustration 都存在的已注册谱面才跳过，部分下载会重试。替换时先保留旧目录为唯一备份，发布失败回滚；成功后旧备份也保留，不删除用户原始内容。

## 排行榜

以前只拿一页/截取后排序，不同模式沿用同一个名次。现在读取完整分页，按分数、误差积分、准确率分别选择每位用户在该 feed 中最好的记录，先计算全体名次，再保留前 20 和自己。同值并列按 1、1、3 排名；自己在前 20 之外仍保留真实名次。分页缺失报错，不以不完整 feed 计算确定名次。这里的准确率排序针对 API 返回的候选记录，不保证找出服务端未返回的全部历史游玩。

官方和 Pro 只读 feed 的合并保留现有功能；缓存按服务器、谱面及误差模式隔离，60 秒失效，上传成功即失效。分页并发限 4；本地榜只在历史变化或模式变化时重建，视口外条目不生成显示字符串/绘制文字。

字体按批绘制、纹理绑定恢复、轨道 seek 二分、FPS 精度和后台时钟修复为跨谱面改进。噪域优化与官方素材、几何审计见 `block-area/README.md`。
